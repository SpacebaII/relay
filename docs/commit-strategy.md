# Suggested Commit Strategy

For a public GitHub history, prefer small commits that each tell one engineering story:

1. `docs: define Relay product scope and architecture`
2. `feat: model the controlled lead workflow`
3. `feat: add D1 persistence and intelligence providers`
4. `feat: build the responsive lead operations dashboard`
5. `test: cover domain rules and browser workflows`
6. `docs: add deployment guide and case study`

The current workspace was produced as one validated vertical slice. If preserving the actual construction history matters, use one honest initial commit rather than manufacturing backdated incremental commits:

`feat: ship Relay lead operations MVP`
